# 【AI 小精靈】把只會單向推播的股票機器人，變成可以追問「為什麼」的 LINE 小精靈（n8n + LINE + Gemini）

## 一、背景：我原本有一個「只會說、不會聽」的機器人

我自己寫了一個台股量化程式 quant-bot（Python），每天收盤後用 GitHub Actions 自動跑兩種規則：

- **突破策略（breakout）**：收盤創 20 日新高就「進場」，跌破 10 日最低就「出場」，中間叫「續抱」
- **低價潛力股評分**：位階低、外資買超、站上均線，三項各 2 分，滿分 6 分

算完之後，用 LINE 官方帳號「書浩專屬投資機器人」推一則訊息給我，長這樣：

[截圖：原本的推播訊息「📈 quant-bot 今日訊號… ⚪ 續抱：2330 台積電…」]

## 二、觀察到的問題

用了幾個月，我發現這種「推播完就結束」的設計有三個痛點：

1. **看得到結論，看不到原因**。訊息說「[6分] 3035 智原 位階35%」，但我常常想不起來 6 分是哪幾項加起來的，也不知道「續抱」離出場還有多遠。
2. **想追問只能自己翻程式**。要知道「2401 現在位階多少」「這週有什麼變化」，得打開電腦重跑程式。
3. **算完就消失**。程式算出來的中間數字（20 日高點、外資買超張數）都沒有存下來，事後想查也查不到。

順帶在整理的過程中，我還抓到自己程式的兩個 bug：

- 「位階 35%」其實是 34.6% 四捨五入的結果，所以才拿到「<35%」的 2 分——只看訊息會以為規則寫錯
- 訊息寫「一年區間」，但程式實際用的是從 2024 年到現在（2 年多）的區間

> 💡 心得：要讓 AI 能「解釋」，資料本身就要先講得清楚。這一步反而讓我把自己的程式修得更正確。

## 三、我的做法

### 3-1 整體架構

```
（既有，不動）GitHub Actions 每天收盤後 ─→ 算訊號 ─→ LINE 推播給我
                                   └─→ 把結果存成 JSON ─→ Cloudflare R2（新增）

（新增）我在 LINE 傳問題 ─→ LINE 平台 ─→ Cloudflare Tunnel ─→ n8n
         n8n：驗證簽章 → AI Agent（Gemini）查 JSON / 查即時股價 → 回覆到 LINE
```

[截圖：n8n 畫布全圖（主流程 20 個節點）]

重點是「**原本的推播完全不動**」，只是多做兩件事：

1. 讓 quant-bot 把計算結果（含所有中間數字）存成 JSON，放到網路上讓 n8n 讀得到
2. 用 n8n 做一個「聽得懂問題、會去查資料、再用白話回答」的小精靈

### 3-2 第一步：讓資料落地（quant-bot 端）

我寫了一支 `export_signals.py`，每天推播完順便輸出兩種 JSON：

- `summary.json`：今天的總覽（哪些續抱、哪些出場、潛力股排名、最近 10 天的進出場紀錄）
- `tickers/2330.json`：單一股票的明細（20 日高點、10 日低點、外資買賣超、每一項評分的原始數字）

關鍵設計：**數字一律保留原始值**（例如位階存 0.346 而不是 35%），另外再放一個給人看的 `display` 欄位。這樣 AI 解釋時不會被四捨五入騙到。

JSON 上傳到 Cloudflare R2（類似雲端硬碟，可以用網址直接讀檔），網址中間加了一段亂數，避免被隨便猜到。

### 3-3 第二步：n8n 是什麼？

沒用過 n8n 的話，可以把它想成「**用積木拼流程的工具**」：每個方塊（節點）做一件事，用線連起來，資料就從左流到右。不用寫完整的程式，也能串接 LINE、AI、各種網路服務。

我把 n8n 用 Docker 裝在自己的 Mac 上，再用 Cloudflare Tunnel 給它一個對外的 https 網址，讓 LINE 找得到它。

### 3-4 第三步：n8n 流程逐個節點解說

| # | 節點 | 它在做什麼（白話） |
|---|---|---|
| 1 | **Webhook** | n8n 的「收件信箱」。LINE 收到使用者訊息後，會把內容寄到這個網址 |
| 2 | **計算簽章（Crypto）** | 用只有我和 LINE 知道的密碼（Channel secret）對信件算一組指紋 |
| 3 | **簽章正確？（IF）** | 指紋和 LINE 附上的 `x-line-signature` 一樣，才代表真的是 LINE 寄來的；不一樣就回 401 拒收 |
| 4 | **回應 200** | 先跟 LINE 說「收到了」，避免 LINE 等太久以為失敗 |
| 5 | **拆開 events** | LINE 一次可能寄來好幾則事件，拆成一則一則處理 |
| 6 | **只留文字訊息（Filter）** | 貼圖、圖片先不處理 |
| 7 | **整理輸入（Code）** | 取出「問題文字、使用者 ID、回覆用的 token」，並記錄這個人今天問了幾題 |
| 8 | **未超過每日上限？（IF）** | 每人每天 30 題，避免 AI 費用失控 |
| 9 | **顯示輸入中** | 呼叫 LINE API，讓聊天室出現「…」動畫，使用者知道小精靈在想 |
| 10 | **AI Agent** | 小精靈的大腦。它會**自己判斷**要不要查資料、查哪一檔，再組織回答 |
| 10a | ┣ Gemini | 大腦用的語言模型（Gemini 2.5 Flash） |
| 10b | ┣ 對話記憶 | 記住同一個人最近 10 輪對話，所以可以問「那它的外資呢？」 |
| 10c | ┣ get_signal_summary | 工具：讀今天的訊號總覽 JSON |
| 10d | ┣ get_ticker_detail | 工具：讀某一檔股票的明細 JSON（AI 自己填股票代號） |
| 10e | ┗ get_realtime_quote | 工具：查證交所即時股價（不在追蹤清單的股票也能查） |
| 11 | **整理回覆（Code）** | 去掉 LINE 不支援的 Markdown 符號、限制長度、**固定附上免責聲明**、加上 4 顆快速按鈕 |
| 12 | **降級回覆** | AI 出錯（例如額度用完）時，改回一句「請稍後再試」，不讓使用者乾等 |
| 13 | **LINE Reply（HTTP Request）** | 把答案用 LINE Reply API 回給使用者 |

[截圖：AI Agent 節點下方掛著 Gemini、記憶、3 個工具的特寫]

另外還有一個獨立的「**錯誤通知**」流程：主流程任何地方出錯，就自動推一則訊息給我。

[截圖：LINE 收到「⚠️ 小精靈出錯了」通知]

### 3-5 給 AI 的「工作守則」（系統提示詞重點）

AI 很會講話，但也很會「亂講」，所以我給它定了幾條規則：

- 每一題都要**先用工具查資料**，數字只能來自查到的資料，不能憑記憶或猜
- 回答要附上資料日期
- **不給任何買賣建議**、目標價，也不用「安全」「值得關注」這種帶評價的字眼
- 被問「要不要買」時，只說明目前訊號狀態與依據
- 免責聲明不交給 AI 自己加，而是由程式在最後**固定附上**，確保每則都有

## 五、踩過的坑（給想做的人）

1. **LINE 會重複回覆**：要到 LINE 官方帳號後台關掉「自動回應訊息」，不然官方的自動回覆和小精靈會一起回。
2. **簽章要對「原始內容」算**：Webhook 要打開 Raw Body。n8n 的 Code 節點不能用 `crypto` 模組，改用內建的 **Crypto 節點**算 HMAC 就解決了。
3. **AI 會一本正經地編答案**：問「這週有什麼變化」時，它一度沒查資料就說「聯發科 10/13 出場」（實際是 10/07）。解法是兩個：在 summary.json 直接提供「近 10 日進出場事件清單」，並在守則規定「每題都要先查工具」。
4. **免費額度比想像中小**：Gemini 2.5 Flash 免費版每天只有 20 次請求（一題約 2 次），測試沒多久就用完；預覽版模型尖峰時段還會回 503。最後開了付費並設預算上限。
5. **Quick Tunnel 網址會變**：免費的 Cloudflare quick tunnel 每次重開網址都不同，要回 LINE Developers 更新 Webhook URL。有自己的網域的話建議用 named tunnel。
6. **錯誤通知寄給了機器人自己**：LINE 寄來的資料裡 `destination` 是「機器人自己的 ID」，`source.userId` 才是使用者，一開始拿錯就會收到「不能傳訊息給自己」。
